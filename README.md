
# Demo for Markdown 2026

[GitHub Markdown](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax) is **a lightweight markup language** used to format text, documentation and README files.

## Markdown Features Not Shown in the Video

[GitHub Flavoured Markdown (GFM)]() offers many additional features. Explore the examples below and follow the links to GitHub's official documentation to learn more.

### 1. Images

Insert images into your README using a URL or a relative file path. Write meaningful alternative text in square brackets that describes what the image shows, rather than simply giving its filename. This is an important accessibility feature, particularly for people using screen readers. For example, the image below uses the alternative text [Mona AI Generated Apprentice Octocat].

![Mona AI Generated Apprentice Octocat](mona_apprentice.png)

[GitHub documentation: Images](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#images)

### 2. Tables

Organise information into rows and columns.

| Language | Purpose |
|----------|---------|
| HTML | Web structure |
| CSS | Styling |
| JavaScript | Interactivity |
| Python | Programming |

[GitHub documentation: Tables](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-tables)

### 3. Task Lists

Create checklists to track progress.

- [x] Create repository
- [x] Write README
- [ ] Add images
- [ ] Complete project

[GitHub documentation: Task Lists](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#task-lists)

### 4. Collapsible Sections

Hide additional information inside expandable sections.

<details>
<summary>Click to learn more</summary>

This information becomes visible when the section is expanded.

</details>

[GitHub documentation: Collapsible Sections](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-collapsed-sections)

### 5. Code Blocks and Syntax Highlighting

Display code using fenced code blocks and specify the programming language for syntax highlighting.

[GitHub documentation: Code Blocks](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-and-highlighting-code-blocks)

### 6. Alerts

Highlight important information using GitHub's built-in alerts.

> [!NOTE]
> This is useful information.

> [!TIP]
> Use descriptive commit messages.

> [!WARNING]
> Never commit passwords or API keys.

[GitHub documentation: Alerts](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#alerts)

### 7. Diagrams

GitHub supports diagrams created using Mermaid, including flowcharts, sequence diagrams and class diagrams.

[GitHub documentation: Creating Diagrams](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)

### 8. Mathematical Expressions

Display mathematical notation using LaTeX syntax.

The equation $a^2 + b^2 = c^2$ is an example of inline mathematics.

[GitHub documentation: Mathematical Expressions](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)

### 9. Footnotes

Add references or explanations without interrupting the main text.

Markdown is widely used for technical documentation.[^1]

[^1]: Markdown was created by John Gruber in 2004.

[GitHub documentation: Footnotes](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#footnotes)

### 10. Emojis

Use emoji shortcodes in Markdown.

:smile: :rocket: :computer: :warning: :white_check_mark:

[GitHub documentation: Emojis](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#using-emojis)

### 11. Strikethrough, Subscript and Superscript

Use additional text formatting options.

~~This text is crossed out.~~

H<sub>2</sub>O

X<sup>2</sup>

[GitHub documentation: Styling Text](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#styling-text)

### 12. Relative Links

Link to other files within your repository.

[View the project documentation](docs/README.md)

[GitHub documentation: Relative Links](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#relative-links)

### 13. Section Links

Create links to headings within the same README.

[Jump to Tables](#2-tables)

[GitHub documentation: Section Links](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links)

### 14. Automatic Links to Issues and Pull Requests

GitHub can automatically recognise issue and pull request references in comments and discussions.

For example, #123 can refer to an issue or pull request in the same repository.

[GitHub documentation: Autolinked References](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/autolinked-references-and-urls)

### 15. Hidden Comments

Add notes to your Markdown source that do not appear in the rendered README.

<!-- Remember to update this section later. -->

[GitHub documentation: Hidden Comments](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github)

### 16. Quoting Text

Use blockquotes to highlight quotations or important statements.

> Good documentation makes a project easier to understand and maintain.

[GitHub documentation: Quoting Text](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#quoting-text)

### 17. Mentioning People and Teams

Mention GitHub users using their usernames.

For example, @octocat.

Mentions can notify users when used in supported GitHub discussions and comments.

[GitHub documentation: Mentioning People and Teams](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#mentioning-people-and-teams)
